# Colab kit locks: time-bounded resolution

The Colab kits install from hash-locked requirement files, one per lane:

| Lane | Input | Lock | Bound | Python |
|------|-------|------|-------|--------|
| 1 (render) | `scripts/colab/locks/lane1.in` | `scripts/colab/locks/lane1.lock` | `scripts/colab/locks/lane1.exclude-newer` | 3.14.9 |
| 3 (train) | `scripts/colab/locks/lane3.in` | `scripts/colab/locks/lane3.lock` | `scripts/colab/locks/lane3.exclude-newer` | 3.12.15 |

`scripts/colab/preflight_resolve.sh` re-runs each lane's `uv pip compile` (uv 0.13.5, the kits'
pin) before any `colab` call and in CI, and refuses `LOCK_DRIFT` when the output differs from the
committed lock.

## Why a bound

The `.in` files float: lane 1 asks for `transformers>=4.28.1`, and every transitive dependency of
both lanes floats the same way. Without a bound, any upstream release after the lock was made
changes what the re-resolve picks, and the drift check fails on every PR with no change of ours.
That happened on 2026-11-06, when transformers 5.22.2 reached PyPI (15:42:54Z) while `lane1.lock`
pinned 5.22.1.

Both the lock compile and the drift check therefore pass uv's `--exclude-newer <instant>`: the
resolver considers only files uploaded before that instant, on PyPI and on the PyTorch index (both
publish upload times). A re-resolve then sees what existed when the lock was made, and an upstream
release can no longer cause `LOCK_DRIFT`. `UV_EXCLUDE_NEWER` and `UV_EXCLUDE_NEWER_PACKAGE` are
cleared for the compile, so only the committed bound applies.

## The timestamp file

`scripts/colab/locks/<lane>.exclude-newer`, committed beside the lock:

```
# uv --exclude-newer bound for lane1.lock: ...
2026-11-06T15:00:00Z
```

- `#` comment lines and blank lines are ignored.
- Exactly one other line: an RFC 3339 UTC instant with whole seconds, `YYYY-MM-DDTHH:MM:SSZ`.
  No offsets, no fractions, no date-only values.
- It must be a real instant and not in the future (a future bound would let later uploads in).
- A missing file is `LOCK_TIMESTAMP_MISSING`; anything else wrong is `LOCK_TIMESTAMP_MALFORMED`.
  The pre-flight checks the file before any compile, also when the compile is mocked in tests.

The drift check leaves uv's two-line header (the "autogenerated" line and the command under it) out
of the comparison: it records how the lock was made, not what it resolves. Locks made before the
bound existed keep their old header until their next re-lock.

## Bumping a lock

A bump is a deliberate PR that moves the bound and re-locks in the same change:

1. Pick the new bound (usually `now`), and edit the lane's `.in` if the inputs change.
2. Run, with uv 0.13.5 on `PATH` or in `UV_BIN`:

   ```bash
   bash scripts/colab/relock.sh lane1 --exclude-newer now
   bash scripts/colab/relock.sh lane3 --exclude-newer 2026-11-20T12:00:00Z
   ```

   `relock.sh` runs the same compile as the drift check (`scripts/colab/lock_common.sh`) and,
   only after it succeeds, writes the lock and its `.exclude-newer` file together. It prints
   `RELOCK_OK lane=… exclude_newer=… pins=… lock_sha256=…`.
3. Move the lock's sha256 pin in the kit: `PINNED_LOCK_SHA` in `launch_lane1_stub.sh` for lane 1,
   `PINNED_OVERRIDE_SHA` in `launch_lane3_stub.sh` for lane 3, and whatever else the kit's
   sha checks then require (its `PINNED_*` block and `tests/colab`). `relock.sh` edits neither.
4. Run `bash scripts/colab/preflight_resolve.sh lane1` and
   `bash scripts/colab/preflight_resolve.sh lane3 --skip-local-wheels`, the `tests/colab` suite,
   and a CPU stub window before any GPU window on the new lock.

## What still floats

- Lane 3's two local wheels (`lycoris-lora`, `diffusers` from a git commit) are outside the
  resolve; they are pinned by sha256 and git commit in `lane3-local-wheels.json` and checked by
  the pre-flight, not bounded by time.
- A file an index removes or replaces in place after the bound (a yank, or a deleted wheel) can
  still change a re-resolve. That is rare and shows up as `LOCK_DRIFT` or `LOCK_COMPILE_FAILED`.
- The bound relies on the indexes' reported upload times.
