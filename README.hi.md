अपनी दृश्य नियम लिखें। कला उत्पन्न करें। प्रत्येक छवि का उन नियमों के विरुद्ध मूल्यांकन करें। परिणामों को संस्करणित, ऑडिट करने योग्य प्रशिक्षण डेटा के रूप में प्रस्तुत करें — फिर प्रशिक्षित मॉडल को वास्तविक उत्पादन वर्कफ़्लो में काम करने के लिए उपयोग करें और सर्वोत्तम आउटपुट को वापस अपने डेटासेट में फीड करें।

स्टाइल डेटासेट लैब आपके कला शैली के बारे में आपके द्वारा लिखी गई चीज़ को उस डेटासेट से जोड़ता है जिससे आप वास्तव में प्रशिक्षण लेते हैं, और फिर उत्पादन के माध्यम से पूरी प्रक्रिया को पूरा करता है। आप एक संविधान परिभाषित करते हैं — सिल्हूट नियम, पैलेट प्रतिबंध, सामग्री भाषा, जो भी आपके प्रोजेक्ट के लिए महत्वपूर्ण है। पाइपलाइन उम्मीदवार उत्पन्न करती है, उनका उन नियमों के विरुद्ध मूल्यांकन करती है, और स्वीकृत कार्यों को पुनरुत्पादनीय डेटासेट में पैकेज करती है, जहाँ प्रत्येक रिकॉर्ड बताता है कि इसे क्यों शामिल किया गया था।

फिर उत्पादन वर्कबेंच कार्यभार संभालता है: प्रोजेक्ट की सच्चाई से पीढ़ी के संक्षिप्त विवरण संकलित करें, उन्हें ComfyUI के माध्यम से चलाएं, आउटपुट की आलोचना करें, अभिव्यक्ति शीट और पर्यावरण बोर्ड को बैच में बनाएं, सर्वोत्तम परिणामों का चयन करें, और उन्हें नए उम्मीदवारों के रूप में फिर से शामिल करें। प्रक्रिया पूरी होती है: उत्पन्न करें, चुनें, समीक्षा करें, मजबूत बनाएं।

## पाइपलाइन

```bash
# Write your canon. Scaffold the project.
sdlab init my-project --domain character-design

# Generate candidates via ComfyUI, then review them
sdlab generate inputs/prompts/wave1.json --project my-project
sdlab sheet outputs/candidates --project my-project   # HTML contact sheet to triage
sdlab curate <id> approved "Strong silhouette, correct faction palette"

# Already have images? Bring them in without generating anything
sdlab ingest ~/renders/wave1 --project my-project

# Measure what the pixels actually are — palette and texture, as numbers
sdlab measure outputs/candidates --project my-project

# Bind approved work to constitution rules
# (`sdlab bind` is a shorter alias for `canon-bind`)
sdlab canon-bind --project my-project

# Freeze a versioned dataset
sdlab snapshot create --project my-project
sdlab split build
sdlab export build

# Build a training package
sdlab training-manifest create --profile character-style-lora
sdlab training-package build

# Compile a production brief and run it
sdlab brief compile --workflow character-portrait-set --subject kael_maren
sdlab run generate --brief brief_2026-04-16_001

# Critique, refine, batch-produce
sdlab critique --run run_2026-04-16_001
sdlab refine --run run_2026-04-16_001 --pick 001.png
sdlab batch generate --mode expression-sheet --subject kael_maren

# Select the best outputs and bring them back
sdlab select --run run_2026-04-16_001 --approve 001.png,003.png
sdlab reingest selected --selection selection_2026-04-16_001
```

वह अंतिम कमांड ही महत्वपूर्ण है। चयनित आउटपुट अन्य सभी चीज़ों की तरह ही समीक्षा प्रक्रिया से गुजरते हैं। डेटासेट बढ़ता है और नियम बने रहते हैं।

## एसेट लेन — प्रशिक्षण डेटा के रूप में 3D निर्यात

`sdlab ingest` बिना किसी जांच के साधारण छवियों को स्वीकार करता है। `sdlab asset ingest` एक **अनुबंध** लेता है।

जब कोई 3D एसेट अपनी स्वीकृति जांच को पास कर लेता है, तो इसे N कोणों से फिर से प्रस्तुत करने से आपको एक ऐसा परिणाम मिलता है जो निर्माण के अनुसार दृश्य-संगत होता है — यह गुण प्रति-दृश्य प्रसार द्वारा गारंटी नहीं दी जा सकती है। एसेट लेन उन निर्यात को स्रोत-आधारित प्रशिक्षण डेटा के रूप में स्वीकार करता है:

```bash
# Validate an export's manifest end to end, run the gates, write nothing
sdlab asset ingest ~/exports/dragon_dense --project my-project --dry-run

# Register it: records, candidates, masks, channels, receipt
sdlab asset ingest ~/exports/dragon_dense --project my-project
```

निर्यात निर्देशिका एक `asset-source.json` घोषणापत्र (स्कीमा **1.3.0**) रखती है जो इसके चैनलों, पैलेट बैंड, गेट थ्रेशोल्ड, स्वीकृति निर्णय, शैली रजिस्टर, यह बताती है कि रेंडर कैसे अस्तित्व में आए, और उनकी पीढ़ी का स्रोत। sdlab प्रत्येक घोषणा को वास्तविक बाइट्स के विरुद्ध साबित करता है और किसी भी उल्लंघन पर पूरी प्रक्रिया को अस्वीकार कर देता है — खराब घोषणापत्र पर कुछ भी पंजीकृत नहीं होता है।

**जोड़:** sdlab तंत्र प्रदान करता है, एसेट अर्थ प्रदान करता है। sdlab कभी भी रे-कास्ट नहीं करता है, कभी भी रेंडर नहीं करता है, और यह कभी नहीं सीखता है कि "स्रोत" नामक एक चैनल विशेष है। यह साबित करता है, मापता है, पंजीकृत करता है और पैकेज करता है। संख्याएँ *क्या* दर्शाती हैं, यह एसेट के साथ रहती है।

अनुबंध क्या लागू करता है:

| चरण | क्या साबित किया गया है |
|---|---|
| **schema** | आकार, आईडी, अच्छी तरह से गठित पैलेट बैंड, और एक स्वीकृति निर्णय जो शाब्दिक रूप से `"accepted"` है |
| **containment** | प्रत्येक संदर्भित पथ निर्यात निर्देशिका के *अंदर* हल होता है (यह अविश्वसनीय इनपुट है) और मौजूद है |
| **encoding** | एक PNG का IHDR इसके घोषित एन्कोडिंग से मेल खाता है; एक NPY हेडर इसके घोषित dtype और आकार से मेल खाता है। एक घोषणापत्र जो "सही दिखता है" लेकिन इसके बाइट्स से असहमत है, वह विफलता वर्ग है जिसे रोकने के लिए यह लेन मौजूद है |
| **categorical** | इंडेक्स्ड PNG स्रोत PLTE ⊆ घोषित पैलेट साबित करते हैं; `nearest`-फ़िल्टर किए गए चैनलों को एक *व्यापक* पिक्सेल डिकोड मिलता है; श्रेणीबद्ध NPY को एक व्यापक मान स्कैन मिलता है |
| **gates** | पैलेट गेट प्रत्येक रेंडर के लिए, घोषणापत्र के अपने बैंड और थ्रेशोल्ड से चलता है — एक विफल रेंडर को जोर से अस्वीकार कर दिया जाता है और इसकी रिपोर्ट की जाती है, इसे चुपचाप स्वीकार नहीं किया जाता है |

रिकॉर्ड **बिना क्यूरेशन के** (`judgment: null`) `provenance.source: "asset"` के साथ आते हैं, जो स्वीकृति ब्लॉक को शाब्दिक रूप से, प्रति-फ़ाइल हैश, कैमरा और व्युत्पन्न पहलू, गेट माप, घोषित शैली रजिस्टर और प्रति-छवि पीढ़ी फ्रेम + बीज को ले जाते हैं। फिर वे अन्य सभी रिकॉर्ड की तरह ही क्यूरेशन प्रक्रिया से गुजरते हैं।

प्रक्रिया यह भी बताती है कि एक घोषणापत्र में *क्या* घोषित नहीं किया गया है — एक अज्ञात शैली रजिस्टर, एक गायब `identity.subject_name`, अनुपस्थित पीढ़ी का स्रोत — इसे विफलताओं के बजाय **नोटिसों** के रूप में। वे रसीद में आते हैं और CLI पर मुद्रित होते हैं। एक ऐसा अंतर जिसके बारे में किसी को नहीं बताया जाता है, वह एक ऐसा अंतर है जिसे कोई भी बंद नहीं कर सकता है; और क्योंकि एक घोषणापत्र *घोषित* कर सकता है कि इसके रेंडर इसके स्वयं के बीज के बिना नियतात्मक व्युत्पन्न हैं, इसलिए लेन कभी भी एक ऐसे निर्यात पर अंतर की रिपोर्ट नहीं करता है जो सही है।

पूर्ण अनुबंध, सत्यापन सीढ़ी और प्रत्येक फ़ील्ड के पीछे का तर्क: [docs/asset-lane-design.md](docs/asset-lane-design.md)।

## मानक निर्माण

डेटासेट पाइपलाइन चलने से पहले, `sdlab canon *` नेमस्पेस आपके प्रोजेक्ट के मानक इकाई भंडार को उन तीन अनुमानों में बदल देता है जिनका वास्तव में प्रशिक्षण और उत्पादन उपयोग करते हैं — और उन प्रविष्टियों को लॉक कर देता है जिन्हें नहीं बदलना चाहिए।

```bash
# Build three projections from the canon entity store:
#   dataset.jsonl  → training adapters
#   prompts/*.j2   → ComfyUI workflow invocation
#   context/*.md   → Role OS narrative dispatch
sdlab canon build --project my-project

# Freeze an entry so regeneration can't silently change it
sdlab canon freeze kael_maren --project my-project --reason "prologue portrait locked"

# Report drift on frozen entries since the last clean build
sdlab canon drift --project my-project
```

एक स्थानीय मॉडल भी मानक का मसौदा तैयार कर सकता है, लेकिन यह कभी भी इसका निर्णय नहीं लेता है। `sdlab canon draft <class_id> --endpoint <url> --brief "<text>" --out <path>` एक लूपबैक-ओनली, OpenAI-संगत सर्वर से एक मानक प्रविष्टि और संकेतों के लिए पूछता है, और उन्हें `status: "draft"`, `judgment: null` और प्रत्येक आउटपुट पर मसौदा मॉडल के साथ लिखता है। जब तक कोई व्यक्ति इसकी पुष्टि नहीं करता है, तब तक एक मसौदे को जमा नहीं किया जा सकता है: फ्रीज गेट किसी भी मॉडल-द्वारा तैयार की गई प्रविष्टि को मानव अनुमोदन, एक कारण और उस सटीक मसौदे के हैश के बिना अस्वीकार कर देता है जिसे अनुमोदित किया गया था।

`canon build` सामग्री-आधारित है — इसका आउटपुट `canon_sha` द्वारा कुंजीबद्ध है और कैश किया गया है, इसलिए एक अपरिवर्तित मानक तुरंत पुनर्निर्मित हो जाता है। `canon freeze` प्रत्येक फ्रीज को एक विशिष्ट बिल्ड के विरुद्ध प्रमाणित करता है और एक `freeze-events.jsonl` ऑडिट ट्रेल में जोड़ता है: `frozen` प्रविष्टियाँ सीधे पुन: उत्पन्न करने से इनकार करती हैं, `soft-advisory` प्रविष्टियाँ डिफ़ॉल्ट रूप से इनकार करती हैं (`--i-know` के साथ बाईपास करें)। `canon drift` प्रत्येक देखी गई प्रविष्टि के हैश की पुनर्गणना करता है और किसी भी चीज़ को चिह्नित करता है जो पिछली स्वच्छ बिल्ड के बाद से चली गई है।

हैंडबुक में पूर्ण वर्कफ़्लो: [मानक निर्माण](handbook/canon-build/), [मानक जमा](handbook/canon-freeze/), और [दो-LoRA स्टैकिंग](handbook/two-lora-stacking/)।

## यह क्या उत्पन्न करता है

सात डेटासेट कलाकृतियाँ और एक पूर्ण उत्पादन वर्कबेंच। प्रत्येक कलाकृति अपने पूर्ववर्तियों से जुड़ी होती है ताकि आप किसी भी प्रशिक्षण रिकॉर्ड को उस नियम तक ट्रेस कर सकें जिसने इसे अनुमोदित किया।

| कलाकृति | यह क्या है |
|----------|-----------|
| **Snapshot** | जमा कॉन्फ़िगरेशन फ़िंगरप्रिंट के साथ जमे हुए रिकॉर्ड चयन। प्रत्येक समावेश का एक स्पष्ट कारण है। |
| **Split** | प्रशिक्षण/मान्य/परीक्षण विभाजन जहाँ विषय परिवार कभी भी सीमाओं को पार नहीं करते हैं। |
| **Export package** | स्व-निहित डेटासेट: घोषणापत्र, मेटाडेटा, छवियां, विभाजन, डेटासेट कार्ड, चेकसम। |
| **Eval pack** | कैनन-जागरूक परीक्षण कार्य: लेन कवरेज, निषिद्ध विचलन, एंकर/गोल्ड, विषय निरंतरता। |
| **Training package** | एडेप्टर के माध्यम से ट्रेनर-तैयार लेआउट (`diffusers-lora`, `generic-image-caption`)। समान सत्य, अलग प्रारूप। |
| **Eval scorecard** | प्रत्येक कार्य के लिए पास/फेल, मूल्यांकन पैक के विरुद्ध उत्पन्न आउटपुट के स्कोरिंग से निर्धारित। |
| **Implementation pack** | संकेत उदाहरण, ज्ञात विफलताएं, निरंतरता परीक्षण और पुनः-संग्रह मार्गदर्शन। |

उत्पादन कार्यक्षेत्र में निम्नलिखित शामिल हैं:

| सतह | यह क्या करता है |
|---------|-------------|
| **Compiled brief** | वर्कफ़्लो प्रोफ़ाइल + प्रोजेक्ट सत्य से निर्धारित नियतात्मक पीढ़ी निर्देश। |
| **Run** | स्थिर निष्पादन कलाकृति: संक्षिप्त + बीज + ComfyUI आउटपुट + घोषणापत्र। |
| **Critique** | कैनन के विरुद्ध रन आउटपुट का संरचित बहु-आयामी मूल्यांकन। |
| **Batch** | समन्वित बहु-स्लॉट उत्पादन (अभिव्यक्ति शीट, पर्यावरण बोर्ड, सिल्हूट पैक)। |
| **Selection** | रचनात्मक निर्णय कलाकृति: किन आउटपुट को चुना गया, क्यों, और वे कहां से आए। |
| **Re-ingest** | चयनित आउटपुट पूर्ण पीढ़ी के प्रमाण के साथ उम्मीदवार रिकॉर्ड के रूप में वापस आते हैं। |

## यह क्यों मौजूद है

किसी भी दृश्य एआई पाइपलाइन में प्रशिक्षण डेटा सबसे महत्वपूर्ण कलाकृति है। लेकिन अधिकांश प्रशिक्षण डेटा छवियों का एक फ़ोल्डर होता है जिसमें कोई इतिहास, कोई निर्णय प्रक्रिया और उस शैली के नियमों से कोई संबंध नहीं होता है जिनका पालन करना था।

स्टाइल डेटासेट लैब इस संबंध को स्पष्ट करता है। आपका संविधान नियमों को परिभाषित करता है। आपका रुब्रिक स्कोरिंग आयामों को परिभाषित करता है। आपका क्यूरेशन निर्णय को रिकॉर्ड करता है। आपका कैनन बंधन संबंध को साबित करता है। और आपका डेटासेट इन सभी को संरचित, खोज योग्य, पुनरुत्पादनीय सत्य के रूप में आगे बढ़ाता है।

व्यावहारिक परिणाम: जब आपका LoRA भटकता है, तो आप *क्यों* पूछ सकते हैं। जब आपके अगले प्रशिक्षण दौर में बेहतर डेटा की आवश्यकता होती है, तो आप जानते हैं कि कौन से रिकॉर्ड लगभग विफल हैं और वे किस एकल नियम में विफल रहे। जब एक नए टीम सदस्य से पूछा जाता है कि परियोजना की दृश्य भाषा क्या है, तो उत्तर एक फिग्मा बोर्ड नहीं है - यह 1,182 वर्गीकृत उदाहरणों के साथ एक खोज योग्य संविधान है।

## उत्पादन में सिद्ध

यह एक डेमो पाइपलाइन नहीं है। दो वास्तविक शैली-एलओआरए इसके माध्यम से अंत-से-अंत तक भेजे गए हैं - समान कैनन → क्यूरेट → ट्रेन → शिप लूप, क्यूरेशन स्पेक्ट्रम के विपरीत छोरों पर।

- **[टैलो फेन](handbook/case-study-tallow-fen/)** (जीव-डिजाइन) - एक स्क्रैच से सर्वश्रेष्ठ कलाकृति, 293 क्यूरेट किए गए रिकॉर्ड में से **~34% अनुमोदन** (169 अस्वीकृत - गेट कठोर रूप से अस्वीकार करता है)। `qwen-image` पर `tallow_fen_style_v3.safetensors` @ 1.5 पर भेजा गया।
- **[रस्टलाइन](handbook/case-study-rustline/)** (अवधारणा-डिजाइन) - घनी, पूर्व-निर्मित कैनन, 180 रिकॉर्ड में से **~96% अनुमोदन**। `qwen-image` पर `rustline_v3ckpt_1500.safetensors` @ 1.0 पर भेजा गया, बाद में एक दूसरी परियोजना द्वारा पुन: उपयोग किया गया।

समान पाइपलाइन, दो उत्पादन प्रोफाइल: क्यूरेशन गेट वास्तविक है (यह खुले विषयों पर कठोर रूप से अस्वीकार करता है), और अनुशासित कैनन उच्च स्वीकृति देता है।

## परियोजना संरचना

प्रत्येक परियोजना स्व-निहित है। पाँच JSON कॉन्फ़िगरेशन फ़ाइलें नियमों को परिभाषित करती हैं; बाकी सब डेटा है।

```
projects/my-project/
  project.json           Identity + generation defaults
  constitution.json      Rules with rationale templates
  lanes.json             Subject lanes with detection patterns
  rubric.json            Scoring dimensions + thresholds
  terminology.json       Group vocabulary + detection order
  records/               Per-asset JSON (provenance + judgment + canon)
  snapshots/             Frozen dataset snapshots
  splits/                Train/val/test partitions
  exports/               Versioned export packages
  training/              Profiles, manifests, packages, eval runs, implementations
  workflows/             Workflow profiles + batch mode definitions
  briefs/                Compiled generation briefs
  runs/                  Execution artifacts (brief + outputs + manifest)
  batches/               Coordinated multi-slot productions
  selections/            Chosen outputs with reasons and provenance
  inbox/generated/       Re-ingested images awaiting review
```

## विश्वास गुण

ये आकांक्षात्मक नहीं हैं। इन्हें लागू किया जाता है।

- **स्नैपशॉट अपरिवर्तनीय होते हैं।** कॉन्फ़िगरेशन फ़िंगरप्रिंट (SHA-256) यह साबित करता है कि कोई बदलाव नहीं हुआ। आईडी को परमाणु रूप से दावा किया जाता है, इसलिए दो समवर्ती रन एक ही निर्देशिका में आपस में नहीं मिल सकते।
- **स्प्लिट्स रिसाव को रोकते हैं - और यह बताने वाला चेक स्वतंत्र है।** विषय परिवार (पहचान, वंश या सामान्यीकृत आईडी स्टेम द्वारा) कभी भी विभाजन सीमाओं को पार नहीं करते हैं, और एक दूसरा चेक विषय की पहचान को खरोंच से फिर से प्राप्त करता है, बजाय इसके कि स्प्लिट द्वारा उपयोग किए गए मानचित्र को फिर से पढ़ा जाए। एक डेटासेट कार्ड केवल तभी "रिसाव: कोई नहीं (सत्यापित)" का दावा करता है जब दोनों चेक चलाए जाते हैं और सफल होते हैं; स्प्लिट जो दूसरे चेक से पहले का है, वह ठीक यही बताता है।
- **मैनिफेस्ट अपरिवर्तनीय अनुबंध हैं।** निर्यात हैश + कॉन्फ़िगरेशन फ़िंगरप्रिंट, और `validate` प्रत्येक फ़ाइल `checksums.txt` को फिर से हैश करता है - इसलिए एक पूर्ण निर्यात के अंदर एक छवि को बदलने पर यह पकड़ा जाता है, जिसमें उन मैनिफेस्ट भी शामिल हैं जो उस चेक से पहले बनाए गए थे।
- **रन अपने सटीक ग्राफ़ को पिन करते हैं।** प्रत्येक पीढ़ी `comfy_workflow_sha` + मॉडल/LoRA सामग्री हैश + बीज नीति रिकॉर्ड करती है, इसलिए एक लहर को बाइट-दर-बाइट दोहराया जा सकता है। JS और Python रनर को एक परीक्षण द्वारा बाइट-समान हैश पर रखा जाता है जो दोनों को उत्पन्न करता है। मॉडल हैशिंग वैकल्पिक है (`--hash-models`) और कभी भी नकली नहीं होता है - एक अनिर्धारित फ़ाइल `sha256: null` को एक नोट के साथ रिकॉर्ड करती है।
- **कोई भी मॉडल अपने स्वयं के आउटपुट को सत्यापित नहीं करता है।** निर्णय `judged_by_model` और `generator_model` रिकॉर्ड करते हैं; यदि वे कभी भी एक ही मॉडल हैं, तो एक चेतावनी जारी होती है।
- **एक निर्णय बताता है कि इसे किसने बनाया।** `eligibility audit` किसी व्यक्ति द्वारा लिखे गए निर्णयों को एक बल्क स्क्रिप्ट द्वारा बनाए गए निर्णयों से अलग करता है, इसलिए एक तर्क जो किसी छवि के बजाय किसी श्रेणी का वर्णन करता है, वह क्यूरेशन के रूप में नहीं माना जा सकता है।
- **माप निर्णय नहीं है।** `sdlab measure` एक रिकॉर्ड में संख्याएँ जोड़ता है। यह कभी भी निर्णय, उपयुक्तता या अनुमोदन निर्धारित नहीं करता है - और जहां किसी छवि के लिए एक माप अपरिभाषित है, तो यह `null` रिकॉर्ड करता है, बजाय किसी संभावित संख्या के।
- **एक रिलीज़ यह साबित कर सकता है कि प्रत्येक छवि कहां से आई।** `sdlab verify --project <name>` प्रत्येक रिकॉर्ड के लिए श्रृंखला को ऑफ़लाइन पर चलाता है: रिकॉर्ड पर मालिक और लाइसेंस, वह कैनन प्रविष्टि जिससे यह जुड़ा हुआ था (हैश द्वारा), प्रत्येक मॉडल और LoRA का लाइसेंस जिसने इसे बनाया (SPDX आईडी, लाइसेंस URL, वह तारीख जिस पर इसे पढ़ा गया था, और फ़ाइल हैश), और रन मैनिफेस्ट में वर्कफ़्लो हैश। एक लापता लिंक चेक को पास करने के बजाय विफल कर देता है।
- **एडेप्टर सत्य को नहीं बदल सकते।** अलग लेआउट, समान रिकॉर्ड। कोई अतिरिक्त नहीं, कोई हटाने नहीं, कोई पुनर्वर्गीकरण नहीं।
- **उत्पन्न आउटपुट समीक्षा के माध्यम से फिर से प्रवेश करते हैं।** कोई बाईपास नहीं। अन्य सभी चीजों की तरह क्यूरेट और बाइंड करें। बाहरी रूप से उत्पन्न छवियां `sdlab ingest` के माध्यम से उसी तरह प्रवेश करती हैं, बिना क्यूरेट किए।
- **विफलताएँ दिखाई देती हैं।** एक लापता रिकॉर्ड, एक ऐसी छवि जिसे रखा नहीं जा सकता, या एक कैप्शन जिसे बनाया नहीं जा सकता, वह एक निर्यात या प्रशिक्षण पैकेज को चुपचाप कम करने के बजाय रोक देता है।

npm install -g @mcptoolshop/style-dataset-lab

इसके लिए Node.js 20+ और स्थानीय होस्ट:8188 पर [ComfyUI](https://github.com/comfyanonymous/ComfyUI) की आवश्यकता होती है।

### इसे ComfyUI के बिना आज़माएँ

आप ComfyUI को स्थापित किए बिना या किसी भी SDXL भार को डाउनलोड किए बिना बंडल किए गए स्टार फ्रेट प्रोजेक्ट का उपयोग करके पूर्ण गैर-उत्पादन सतह - निरीक्षण, क्यूरेशन, स्नैपशॉट, स्प्लिट, निर्यात - का पता लगा सकते हैं।

```bash
# Scaffold a fresh project (no ComfyUI needed)
sdlab init test --domain game-art

# Run the canonical health check (no ComfyUI needed)
sdlab project doctor --project test

# Dry-run a snapshot against the bundled Star Freight corpus
sdlab snapshot create --dry-run --project star-freight
```

`sdlab project doctor` प्रत्येक प्रोजेक्ट कॉन्फ़िगरेशन (संविधान, लेन, रूब्रिक, शब्दावली) को मान्य करता है और GPU को छुए बिना पात्रता की रिपोर्ट करता है। कोई भी कमांड जो उत्पन्न स्थिति को बदलता है, वह पहले प्रभाव का पूर्वावलोकन करने के लिए `--dry-run` स्वीकार करता है।

यदि आप `--project` को भूल जाते हैं, तो CLI `projects/` के तहत पाए जाने वाले पहले प्रोजेक्ट पर वापस आ जाता है और एक चेतावनी प्रिंट करता है - इसे चुप कराने के लिए `--project` को स्पष्ट रूप से पास करें।

### एक बाधित रन को फिर से शुरू करना

लंबे समय तक चलने वाले उत्पादन रन को बिना पूर्ण किए गए काम को दोहराए फिर से शुरू किया जा सकता है:

```bash
# Skip subjects whose record + image are already on disk.
# Seeds are preserved — resumed runs are bit-identical to fresh ones.
sdlab generate inputs/prompts/wave1.json --project my-project --resume

# Re-run only failed/missing slots in an existing batch.
# Inherits mode/subject/theme from the prior manifest.
sdlab batch generate --resume batch_2026-04-22_001 --project my-project
```

दोनों कमांड काम करते हैं क्योंकि प्रत्येक स्लॉट अपनी मैनिफेस्ट प्रविष्टि को परमाणु रूप से लिखता है क्योंकि यह समाप्त होता है - रन के बीच में क्रैश कभी भी आंशिक स्थिति को दूषित नहीं करता है।

ComfyUI नहीं चल रहा है। ComfyUI (`python main.py --listen 127.0.0.1 --port 8188`) शुरू करें और `curl http://127.0.0.1:8188/system_stats` के साथ पुष्टि करें। किसी भिन्न होस्ट/पोर्ट को इंगित करने के लिए, `COMFY_URL=http://host:port` सेट करें।

**`missing checkpoint` / `LoRA weight not found`**
आपके वर्कफ़्लो प्रोफ़ाइल में एक मॉडल फ़ाइल का नाम है जो ComfyUI के `models/checkpoints/` या `models/loras/` फ़ोल्डर में नहीं है। `projects/<project>/workflows/profiles/<profile>.json` खोलें, `checkpoint` या `lora` फ़ील्ड का पता लगाएं, और या तो संदर्भित भार डाउनलोड करें या इसे किसी ऐसे भार से बदलें जो आपके पास पहले से है। समाधान की पुष्टि करने के लिए `sdlab project doctor --project <project>` को फिर से चलाएँ।

**`sdlab project doctor` त्रुटियाँ**
डॉक्टर संरचित त्रुटि कोड लौटाता है। सामान्य:
- `E_PROJECT_NOT_FOUND` - प्रोजेक्ट निर्देशिका `projects/` के तहत मौजूद नहीं है। वर्तनी की जाँच करें।
- `E_CONFIG_INVALID` - पाँच JSON कॉन्फ़िगरेशन फ़ाइलों में से एक स्कीमा सत्यापन में विफल रहा। `hint` फ़ील्ड खराब फ़ाइल और फ़ील्ड का नाम देता है।
- `E_RECORD_DRIFT` - किसी रिकॉर्ड के कॉन्फ़िगरेशन फ़िंगरप्रिंट अब इसके स्रोत से मेल नहीं खाते हैं। संकेत के अनुसार फिर से क्यूरेट या फिर से बाइंड करें।

**`No --project specified, falling back to <name>`**
एक नरम चेतावनी। सही प्रोजेक्ट का चयन करने और चेतावनी को शांत करने के लिए `--project <name>` को स्पष्ट रूप से पास करें।

**पेंटरली / VRAM आउट-ऑफ़-मेमोरी समस्याएँ**
पेंटरली डेनोइज़ ट्यूनिंग नोट्स के लिए `docs/internal/HANDOFF.md` देखें। संक्षेप में: डेनोइज़ शक्ति को कम करें, बैच आकार को कम करें, या अपने वर्कफ़्लो प्रोफ़ाइल में एक छोटे चेकपॉइंट पर स्विच करें।

**बग की रिपोर्ट करना**
https://github.com/mcp-tool-shop-org/style-dataset-lab/issues पर एक समस्या फ़ाइल करें, जिसमें आपका sdlab संस्करण (`sdlab --version`), Node संस्करण (`node -v`), पूर्ण कमांड और संरचित त्रुटि आउटपुट शामिल है। एक बग-रिपोर्ट टेम्पलेट फ़ील्ड को पहले से भर देता है।

## सुरक्षा

डिफ़ॉल्ट रूप से स्थानीय। कोई टेलीमेट्री नहीं, कोई एनालिटिक्स नहीं, और `sdlab` CLI से कोई बाहरी अनुरोध नहीं: छवियां आपके GPU और फ़ाइल सिस्टम पर रहती हैं, और `canon draft` किसी भी गैर-लूपबैक एंडपॉइंट को अस्वीकार कर देता है।

एकमात्र अपवाद ऑप्ट-इन है। `scripts/colab/` आपके अपने Google Colab खाते पर रेंडर या LoRA प्रशिक्षण चरण चलाने के लिए लॉन्च किट रखता है। वे केवल उन फ़ाइलों को अपलोड करते हैं जिन्हें आप निर्दिष्ट करते हैं, आपके लाइव Colab बैलेंस से प्राप्त खर्च सीमा के तहत चलते हैं, और बाहर निकलने पर अपना सत्र समाप्त कर देते हैं। ये किट **प्रायोगिक** हैं: अभी तक इनका पूरी तरह से परीक्षण नहीं किया गया है।
